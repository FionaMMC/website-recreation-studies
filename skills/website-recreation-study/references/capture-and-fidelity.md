# 公开资源与保真实现：选择依据和技术陷阱

这是条件性参考，不是每个网站都应采用镜像或保留编译代码。

## 先问路线是否解决真实问题

优先重建可读 React 组件。保留原始编译 UI 适用于：参考公开可访问、保真有明确收益、关键 motion 依赖难以用截图推断，且交付目标允许明确区分参考实现与独立模式库。否则用真实素材独立实现。

两层成果应有真实差别：

| 层 | 用途 | 技术与归属说明 |
| --- | --- | --- |
| 忠实参考 | 保存该日期的外观和行为，供对照研究 | 可能包含原始 CSS、资源和 vendor 模块；不等于自有源码 |
| 自有模式 | 在其他产品复用、修改、换主题与内容 | 可读 JSX、公开 props、独立样式与依赖说明，不靠源站 module ID 运行 |

不要为了“看起来是 React 项目”而只把截图、iframe 或静态 HTML 放进 React 壳。最终应明确说明实际实现方式与保留依赖。

## 资源闭合比下载 HTML 多一步

先收集当前页面真正使用的资源与公开路径，再按依赖补齐。保留源路径通常更稳；改路径时，除了 HTML 还要考虑 CSS `url()`、`@import`、动态脚本、运行时图片路径和字体。只抓首屏可见图片会漏掉菜单、页脚、轮播与懒加载内容。

资源清单建议记录 `source_url`、`local_path`、`kind`、`captured_on` 和归属。拒绝下载整个站点来碰运气；不依据任意字符串自动抓取 API、跟踪地址、账户页或所有框架路由。外部 URL 保留为外部依赖并说明。

## SSR 与 hydration

有完整服务器 HTML 不代表静态页面会显示：标题或图片可能初始透明，依赖 hydration 和动画状态才出现。需要检查稳定状态、控制台和实际控件。清洗 HTML 应保留 SVG 属性、遮罩、data 属性、根容器和必要数据；普通 HTML 解析器可能改写 SVG 属性大小写。

只在有必要时恢复编译运行图。不同站点可能不是 Next，不应预设框架或 webpack。若使用原始 React 组件图，React/ReactDOM 与 Hooks 必须兼容；避免并存不同 React 实例。路由、Head、图片与应用 contexts 可能是隐含依赖。适配层隔离这些条件，不把复杂性泄漏给通用组件。

Lightspark 首例保留了公开 Next 模块，以兼容层复用同一 React 单例和上下文，随后单独写了 5 个模式。这证明该站点的路线有效，不证明它是其他站点最优解。案例文件是历史证据：`lightspark-replica/src/lib/runtime.js`、`src/providers/WebsiteProvider.jsx`、`src/patterns/`。chunk 哈希、模块编号、React 版本与打补丁字符串每次重新确认，不复制成通用规则。

## 统计、服务和跳转

删除 HTML 中的 GTM/广告标签可能不够，应用 effect 还可能注入脚本。检查网络或实际注入逻辑，只停用与 UI 无关的生产跟踪，不破坏必要组件。被移除 SDK 提供的可见控件必须本地接住，或明确说明替代行为。

复制首页通常不包含业务后台。可将产品、文档、登录、预约等指向真实目标，但要同时覆盖：普通 `<a>`、修改键打开、JS `location.assign`/router，以及 Next 等框架的自动预取。不要让未实现二级路由成为 404 或伪造提交成功。

## 本地工具与可复现性

使用当前环境支持的浏览器入口和预览工具，不发明备用控制通道。启动服务后先验 HTTP 成功，再展示。文件服务器应正确处理站点根路径、MIME 和字体；本例曾出现根目录尾斜线造成错误 403。借助现有 Vite 服务通常比新写服务器稳妥。

对于打包器，不必要的根路径 `<link rel="preconnect" href="/">` 可能被误判为目录资源；遇到构建错误时查具体引用，不笼统移除全部 head。保留真实换行和路径，所有安装版本以锁文件和当前项目为准。

## 视觉对照

记录 viewport 和状态。动态首屏的不同时间点可能本来就不一样，因此先比较字体、容器、卡片尺度、分布、色彩和行为，再判断差异。滚到相关位置确认懒加载，不能把屏外未加载图片全都报告为破图。初始模糊和透明也可能只是入场动画，需确认最终可读状态。
